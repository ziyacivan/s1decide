# ADR 0004 — Licence allowlist for training data, enforced by a test

- **Status:** **accepted** (2026-09-17)
- **Date:** 2026-09-17, end of Phase 0
- **Deciders:** project owner (human), eval-scientist and data-engineer roles
- **Supersedes / superseded by:** —

## Context

`CLAUDE.md` commits to releasing under **Apache 2.0**: code, the BF16 LoRA adapter, the merged
weights and our GGUFs. That commitment constrains the training data, because weights derived
from data that forbids commercial use cannot honestly carry a permissive licence.

Phase 0 Step 5 evaluated against `pngwn/system-one-decisions`, which is **CC-BY-NC-4.0** —
non-commercial. Using it to *measure* a model is fine and is all that was done. Using it to
*train* one would quietly contaminate the release. The problem is that nothing in the
repository would have stopped that: the licence was a sentence in a dataset card, and dataset
cards do not fail builds.

This ADR exists because the failure mode is silent, late and expensive. A licence violation
discovered after training is discovered after GPU-hours, after a model card, possibly after a
publication.

## Decision

**1. `pngwn/system-one-decisions` is eval-only, permanently.** It never appears in a train
split. It remains valuable precisely because we did not train on it: an eval set we have never
fitted is a better yardstick, so this costs us nothing we wanted.

**2. Phase 1 rebuilds training data from the underlying sources under their own licences**, with
our own pipeline in `data/build/`, rather than reusing a derived dataset whose licence is more
restrictive than its inputs.

**3. Every row carries a `license` field, and every row in a train split must carry a licence
from this allowlist:**

| Allowed for training | |
|---|---|
| `Apache-2.0` | |
| `MIT` | |
| `BSD-2-Clause`, `BSD-3-Clause` | |
| `CC0-1.0` | public domain dedication |
| `CC-BY-3.0`, `CC-BY-4.0` | attribution only; attribution is recorded in the dataset card |

**Anything NC (non-commercial) or ND (no-derivatives) may be tagged `eval` only.** Anything not
on the allowlist and not explicitly classified is refused rather than assumed — an unknown
licence is a blocker, not a default-allow.

**4. The gate is a test, not a comment.** `data/build/` exports a licence-gate function, and
`tests/` fails if any row in a train or validation split carries a licence outside the
allowlist. It runs in the normal `uv run task test` suite, with no GPU and no network, against
the committed `data/processed/` manifest. A comment saying "don't train on NC data" is worth
nothing at 2 a.m. three months from now; a red test is worth everything.

### Shape of the gate (specification for Phase 1)

Not implemented yet — Phase 1, item 1. Specified here so it is built to this contract:

- `TRAIN_LICENCE_ALLOWLIST: frozenset[str]` — the table above, in one place.
- `classify_licence(spdx: str) -> Literal["train", "eval-only", "refused"]` — allowlist hit is
  `train`; a recognised NC/ND licence is `eval-only`; anything else is `refused`.
- `assert_train_splits_are_licensed(rows) -> None` — raises, naming the offending source,
  licence and row count. Called by `uv run task data` at the end of the build **and** by a test
  over the committed manifest, so the gate holds whether or not anyone re-runs the build.
- `docs/dataset-card.md` is generated with a per-source licence and split-eligibility column,
  so the card cannot drift from the gate.

## Alternatives considered

- **Keep it a documented convention.** Rejected: it is exactly what we had, and it would have
  permitted the mistake.
- **Review licences only at release time.** Rejected: that is after the GPU-hours, and it
  creates pressure to rationalise rather than retrain.
- **Release under a non-commercial licence instead.** Rejected by the project owner; the point
  of the project is an openly usable alternative, and `CLAUDE.md` says Apache 2.0.

## Consequences

- Phase 1 opens with a **source audit**: every dataset named in `AGENTS.md` for the
  `data-engineer` role gets its licence resolved to an SPDX identifier and classified before a
  single row is fetched. Some named sources will not survive this — banking77, MASSIVE, MMLU,
  Yelp and GoEmotions each have their own terms, and at least one is likely to be eval-only.
  Finding that out at audit time is the point.
- The eval set and the training set will no longer be drawn from the same distribution. That is
  a genuine downside: a train/eval mismatch makes the numbers harder to interpret. It is
  preferable to a licence violation, and it is partly mitigated because held-out families and
  OOD sets were always part of the plan.
- Synthetic data generated by an open-weight teacher inherits the teacher's licence terms; the
  teacher, its licence and the prompt hash are recorded per `CLAUDE.md`'s hard rules.
- If a source's licence is ambiguous, the gate refuses it. Resolving an ambiguity requires a
  human decision recorded here, not a judgement call inside the pipeline.
