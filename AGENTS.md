# AGENTS.md — s1decide

Instructions for any coding agent working in this repository (Claude Code
sub-agents, Codex, Cursor, Aider, etc.). `CLAUDE.md` holds project context,
locked decisions and hard rules and takes precedence; this file defines
**roles, hand-offs and checklists**. Read both.

## Global agent protocol

1. Read `CLAUDE.md`, then `docs/research/landscape-2026-09-24.md` and
   `docs/research/jev-landscape-2026-09-17.md`, then
   the ADRs in `docs/adr/`, then `git log --oneline -20`.
2. Announce which role below you are acting in. Stay in one role per task
   unless the task is explicitly cross-cutting.
3. Plan → confirm → execute → verify → summarise. The summary lists files
   changed, tests added, commands run, and anything the human must decide.
4. You may run `git commit` locally. You may **not** `git push`, publish to
   Hugging Face, or launch a paid cloud job without a human "go" in the same
   session.
5. Never write a metric by hand. Metrics come from `eval/` scripts and live
   in `results/`.
6. Never place private or company data anywhere in the repo.
7. If a fact is needed and not in `docs/research/`, search, verify, then add
   it there with the date before relying on it.
8. When you touch the prompt format, bump `FORMAT_VERSION`, update
   `docs/format-spec.md`, run `uv run task smoke`.
9. This machine is **Windows 11 + PowerShell + RTX 3090 with Unsloth Studio
   installed natively**. Write cross-platform Python; never assume bash,
   `make`, symlinks, FlashAttention or vLLM locally. Run `uv run task doctor`
   at session start and paste its summary in your first message.
10. Unsloth Studio (web UI) is a sandbox for exploration and quick sanity
    trainings only. Anything that ends up in `results/` or on Hugging Face
    must come from `train/` and `eval/` scripts (Unsloth Core).

## Roles

### 1. `architect`
Owns: `docs/adr/`, `docs/format-spec.md`, `src/s1decide/primitives.py`,
`src/s1decide/prompt.py`, `src/s1decide/tokens.py`.

Responsibilities
- Keep the three primitives and the prompt format coherent and versioned.
- Write ADRs for any deviation from the locked decisions in `CLAUDE.md`.
- Guard the invariant: **no decode loop**; one forward pass per call.

Checklist before hand-off
- [ ] `docs/format-spec.md` shows a full rendered example for each primitive
      and for a 4-question mixed call.
- [ ] Option tokens are verified single-token for the Qwen3.8 tokenizer
      (`tests/test_tokens.py`), including after a leading space.
- [ ] Chat template renders with reasoning **off** (test asserts no `<think>`).

### 2. `data-engineer`
Owns: `data/build/`, `data/processed/`, `docs/dataset-card.md`.

Responsibilities
- Fetch and normalise public sources into the unified jsonl schema.
  Starting set: `pngwn/system-one-decisions`, banking77, clinc150, MASSIVE
  (keep Turkish + other non-English subsets), MNLI/ANLI/FEVER/BoolQ → Noul,
  SST-5 and review ratings → Score, plus synthetic structured-state tasks.
- Record source, license and split provenance per row.
- Augmentation: shuffle options, paraphrase option labels, inject
  `other`/`none of the above` variants, bundle 5–30 questions per state so the
  parallel format is seen in training.
- Synthetic labels only from open-weight teachers; log teacher + prompt hash.

Checklist before hand-off
- [ ] `uv run task data` is deterministic (seeded) and idempotent, on Windows and Linux (paths via `pathlib`, files UTF-8/LF).
- [ ] No row leaks between train / val / test by `state` hash.
- [ ] Held-out *families* exist (whole task families unseen in training),
      plus ≥ 2 fully OOD sets reserved for `eval-scientist`.
- [ ] `docs/dataset-card.md` lists every source with license and row counts
      generated by script.

### 3. `training-engineer`
Owns: `train/`, `train/configs/`.

Responsibilities
- Stage 1: Unsloth Core QLoRA SFT (`FastLanguageModel`, 4-bit base,
  gradient checkpointing `"unsloth"`, SDPA attention) on option-token
  cross-entropy (SALSA-style); ordinal loss for Score. Configs for
  `rtx3090_windows` (smoke/iteration) and `h100_linux` (final).
- Stage 3: GRPO with Brier/log-score reward (RLCR-style) via Unsloth + TRL.
  `h100_linux` only.
- Verify Unsloth/PEFT/TRL compatibility with Qwen3.8's GDN hybrid layers on
  day one (Unsloth already ships Qwen3.5 recipes — same family — so start by
  checking whether 3.8 is in their supported list); write
  `docs/adr/0002-base-model.md` with the result.
- If a run works in Unsloth Studio but fails in `train/`, diff the arguments
  Studio used and port them explicitly.
- Log VRAM peak, tokens/s, loss curves; save adapters as BF16 safetensors.
  Close Unsloth Studio before training (VRAM).

Checklist before hand-off
- [ ] `uv run task smoke` passes on the 3090 (Windows) in ≤ 5 min.
- [ ] Config has `hardware:` set; runner refuses mismatched hardware/OS.
- [ ] Script has a `if __name__ == "__main__":` guard, `num_workers=0`
      default, no `flash_attn` import, no bash subprocess calls.
- [ ] Adapter evaluated on **both** BF16 base and 4-bit base; delta reported
      (QLoRA adapters can drift when applied to BF16).
- [ ] No `.generate()` with `max_new_tokens > 1` anywhere in `train/`.

### 4. `inference-engineer`
Owns: `src/s1decide/engine/`, `src/s1decide/decide.py`, `src/s1decide/calibrate.py`,
`src/s1decide/server.py`, `scripts/convert_gguf.sh`, `scripts/merge_lora.py`.

Responsibilities
- Implement KV-cache broadcast: prefill state once, one batch row per
  question, single forward pass, read logits at the answer position.
- Engines: `hf` (transformers/PEFT, optional Unsloth fast path), `llamacpp`
  (GGUF via `llama-cpp-python`; prebuilt CUDA wheel or build with the VS
  Build Tools the Studio installer left), `mock` (CPU/CI), and `vllm`
  (`prompt_logprobs`) as a Linux/WSL2-only optional extra guarded by
  `sys.platform`. All engines pass the same contract tests; vLLM tests skip
  on Windows.
- Two-stage path for > 26 options.
- Temperature scaling fitted per option-count bucket and per quantization;
  stored alongside the model in `calibration.json`.
- `/decide` FastAPI server mirroring the primitive schema.

Checklist before hand-off
- [ ] Fuzz test: 10k random schemas → zero off-schema outputs (type safety by
      construction).
- [ ] Contract tests pass identically on all engines (within tolerance).
- [ ] `uv run task bench` meets the latency targets in `CLAUDE.md`'s definition of
      done (bundling speedup, marginal cost per question, fitted cost model, format
      overhead). The old "64-question < 2× 1-question" rule was retired by ADR 0003:
      KV broadcast amortises the state, not the questions.
- [ ] `scripts/convert_gguf.py` produces Q5_K_M / Q4_K_M (Q8 is v0.2, ADR 0006) from merged BF16
      using llama.cpp's converter, and the same command works on Linux.
- [ ] KV-broadcast implementation is verified against the GDN hybrid cache
      (Mamba-style state + attention KV): broadcasting must copy **both**
      parts; add a test that N-row broadcast equals N independent runs.

### 5. `eval-scientist`
Owns: `eval/`, `results/`, `docs/model-card.md` (metrics sections).

Responsibilities
- Metrics: accuracy, ECE (15 equal-mass bins), Brier, NLL, AUROC of
  confidence-vs-correctness, per option-count bucket (2 / 3–5 / 6–16 / 17–77).
- Always include the **base-rate negative control** and the **zero-shot
  base model** as rows.
- Fair LLM baselines: same model with constrained decoding + logprobs, values
  only; at least one other open model. No baseline that autoregressively
  emits the schema.
- Head-to-head against `evals.typesafe.ai` on the strict common subset;
  state the "reference = frontier-model average" caveat verbatim in the report.
- Quantization table and reliability diagrams.

Checklist before hand-off
- [ ] Every number in any `.md` traces to a `results/<run>/metrics.json`.
- [ ] Reliability diagrams committed as PNG with the JSON that produced them.
- [ ] OOD sets were never touched by `data-engineer` augmentation or
      `training-engineer` runs (check `git log -- data/processed/ood/`).

### 6. `release-manager`
Owns: `README.md`, `docs/model-card.md` (non-metric sections), `pyproject.toml`,
`scripts/push_hf.py`, `CHANGELOG.md`, licensing.

Responsibilities
- Apache 2.0 for code and weights; confirm every dataset license permits
  redistribution of derived weights.
- Model card: base model + commit hash, adapter rank/targets, data sources,
  teacher models, all hyperparameters, hardware, known failure modes,
  intended use ("not a chat model"), how to reproduce.
- Artefacts: BF16 adapter (primary), merged BF16, our GGUFs, `calibration.json`,
  `format-spec.md` copy, example notebook.
- Naming: no "Jev", "TypeSafe", "System One Model" in identifiers.

Checklist before hand-off
- [ ] Fresh-clone `uv run task setup` then `uv run task smoke` green on
      Windows (this machine) and on a Linux runner.
- [ ] `pip install .` then a 10-line quickstart runs on CPU with a tiny mock
      engine (so the README example is testable in CI).
- [ ] Human "go" recorded in the session before `scripts/push_hf.py` runs.

When finishing a task, end with:

```
ROLE: <role>
CHANGED: <files>
TESTS: <added/updated> — `uv run task test` <pass/fail>, `uv run task test-gpu` <pass/fail/skipped>
ENV: <output of `uv run task doctor` summary line, or "not run">
RESULTS: <results/<run_id> or "none">
NEEDS HUMAN: <decisions, approvals, money, publishing — or "none">
NEXT: <recommended next role + task>
```

## Anti-patterns (stop and reconsider)

- Generating text to parse an answer out of it.
- Reporting ECE without Brier and the base-rate control.
- Fitting calibration in BF16 and shipping Q4 with it.
- Adding a dataset without a license line.
- Copying TypeSafe's marketing framing ("can't hallucinate", "frontier").
  We say: type-safe by construction, calibration measured and published.
- Starting an H100 job because "it will probably work".
- Hard-coding Windows paths, `\\` separators or `C:\` anywhere in code.
- Copying a working Unsloth Studio run's numbers into a report instead of
  re-running it through `train/` + `eval/`.
